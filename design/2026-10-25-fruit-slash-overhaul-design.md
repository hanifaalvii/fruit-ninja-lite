# Fruit Slash Overhaul - Design

Note: stored in `design/`, not `docs/`, because `deploy.sh` wipes `docs/`.

## Goal
Make Fruit Slash (Python/pygame + pygbag, existing Supabase leaderboard) look and feel closer to real Fruit Ninja: smooth, 3D-looking, colourful and varied, with a better loading screen, music and sound. The 4 modes stay.

## Priority: best quality (revised)
The user prefers best visuals/sound/animation over small size. Asset files are allowed and wanted.
- Real asset files in `assets/` (images, OGG audio, music). Only CC0 / permissively licensed assets (e.g. Kenney, OpenGameArt CC0, freesound CC0) or ones generated by us; each recorded with its source and licence in `assets/CREDITS.md`. No copyrighted Fruit Ninja assets.
- Procedural/synthesized sound stays as a fallback if a file is missing.
- Still sensible: assets preloaded behind the interactive loading screen with a real progress bar; OGG for audio (web-compatible); keep a 60 FPS target with adaptive particle quality so phones do not stutter; build size is no longer capped but we report it.

## Audience and non-negotiables (clarified)
- Deliverable is the playable game only (no video). Clients open it via a link in a phone or laptop browser, so first impressions matter: impressive 3D-looking animation, and it must never lag, glitch or feel slow.
- Smoothness beats effect count: 60 FPS target on mid phones and laptops, fixed-timestep logic, no per-frame allocations or per-pixel loops, pre-rendered/cached sprites, adaptive quality that sheds effects before dropping frames, no visible hitches during asset loading or when music starts.
- Quality asset files are used, but sized sensibly (compressed OGG, optimised PNG/WebP sprite sheets) so the loading screen finishes fast on mobile networks.
- Acceptance: desktop headless frame-time test (p95 < 16.7 ms for gameplay frames), pygbag build loads and runs in a browser (checked with Playwright), no console errors.

## Structure (game/ package)
`main.py` (thin entry for pygbag) plus `game/`: `audio.py`, `sprites.py`, `entities.py`, `effects.py`, `ui.py`, `modes.py`, `progress.py`, `scenes.py`, `net.py`, `settings.py` and `ARCHITECTURE.md`. `leaderboard.py` and `config.py` stay. Behaviour of existing features is preserved while moving code.

## 3D look
- Pre-rendered fruit sprites: sphere shading, specular highlight, rim light, skin texture, soft drop shadow. Cached at 24 rotation steps.
- Sliced halves with juicy cross-section, independent physics and spin.
- Slight scale wobble with height for depth.

## Animated world
- Parallax gradient sky, drifting clouds, swaying leaves; colour shift between waves.
- Persistent juice splats on the background that fade slowly.
- Screen shake on bombs, slow-mo on bomb hit and last life, glowing blade trail with tail.

## Loading screen
Slice-able floating fruit while stages build; progress bar fills with progress and slices; rotating tips; music starts on first tap (browser autoplay rule).

## Audio
Asset-based (OGG) with synthesized fallback: 3 music tracks (menu, play, tense), fruit-specific slice sounds, rising-pitch combo sound, power-up jingles, music ducking on bomb. Music/effects sliders and mute remain.

## Gameplay
- Combos x2-x5 on fast chains; bonus for 3+ fruit in one swipe.
- Power-ups: slow-mo, double score, fruit-rain, with timer bars.
- Boss giant watermelon with HP bar every N waves (Classic).
- Difficulty: Easy / Normal / Hard (spawn rate, bomb chance, lives).
- Daily challenge (date-seeded goal) and about 12 achievements.
- Unlockable blade trails and backgrounds.
- Progress in localStorage (web) or `save.json` (desktop).
- Leaderboard: unchanged; per mode, personal bests only.

## Menu UI
Animated menu, bobbing logo, mode cards that tilt on hover, settings, achievements and unlocks screens. Works with touch and mouse; landscape layout as now.

## Testing
Headless pygame (SDL dummy drivers) checks: every scene updates/draws; combo maths; daily seed determinism; save round-trip; sprite-cache build time; frame-time measurement. `pygbag --build` smoke test and build-size check.

## Risks
WASM per-frame cost (mitigated by caching and adaptive quality); no real-phone test available here (build check plus desktop timing only).
